# Decisions made during the build

One line each: what was decided, and why, when the plan didn't cover it.

- `LLMError` lives in `squad/llm.py` from Task 0 so `tests/fakes.py` can import it; Task 4 adds `LLM` to the same file.
- WhatsApp pairing is skipped for now (user choice 2026-10-25): `wa-voice` is built and tested, nudges use DMs until paired.
- Track 3 submission is held until the user records the demo video.

## Wave 1 (builders' choices)
- T3: transit_tip on Rides is empty exactly when transit_ids is empty: if transit_ids is empty, every rider already has a seat, so the plan's two conditions are the same check.
- T3: A building code is a 2-6 letter code in brackets at the end of the stripped location, matched case-insensitively with the regex \([a-z]{2,6}\)$, so 'Coor Hall 174 (COOR)' counts as Tempe.
- T3: ' mu ' is matched against the lowercased location padded with a space on each side. That means 'MU' still matches at the start or end of the string, and words that merely contain 'mu', like 'museum', do not.
- T3: Members with seats <= 0 are riders. A driver's car takes the next riders in name order up to that driver's seats; anyone left over goes to transit_ids.
- T7: Priya's 'all six slots' = list(FREE_SLOTS) so it tracks the constants.
- T7: Leo gets no_go=[] (plan lists none); Jordan's 'weeknights' uses the FREE_SLOTS key 'weeknights'.
- T7: persona_busy converts week_of to tz, takes that local date's Monday, and builds tz-aware blocks with datetime.combine(date, time(h), tz); members without blocks (Jordan, Priya, real members) get [].
- T7: persona_busy keeps busy times in a private _BUSY table keyed by member id (days after Monday, start hour, end hour) instead of filling Member.demo_busy, because the plan says the blocks are relative to week_of.
- T7: INTRO_LINES and DEMO_VOTES are keyed by the short name (maya/jordan/priya/leo), not 'demo:<name>', following the plan's wording.
- T2: slot_covers: converts to the local tz and checks that the start's weekday is in the slot, that the start is at or after the slot's start hour on that day, and that the end is at or before day-midnight + end_hour (so end hour 24 means midnight of that day). An unknown slot key returns False.
- T2: is_free with busy: a block overlaps if b.start < end and b.end > start - TRAVEL_MIN, so a block that touches the window edge exactly does not count.
- T2: in_quiet_hours: an unknown quiet_hours key falls back to QUIET_HOURS['22-9'].
- T2: late rule: start hour >= 22, or event.end later than 22:00 on the start's local date. The plan gives no detail_private for 'late', so I used 'it runs past 10pm'.
- T2: Event text for the regex and no_tag matching comes from matching._searchable, which is imported rather than redefined (it is private, but it already exists). Matching is case-insensitive.
- T2: request_allows.exclude_no_go: keys whose regex is None (like 'late') are skipped, because latest_hour already covers time. Unknown keys are ignored.
- T2: Learned filters with a malformed value (int/float ValueError or a bad regex) are treated as not matching instead of raising, because their values come from parsed chat replies.
- T2: Added 2 tests beyond the plan's list: test_busy_none_uses_slots and test_malformed_learned_filter_is_ignored.
- T1: campus_events.py is a byte-for-byte copy with only the SAMPLE line changed to Path(__file__).parent / "assets" / "sample_campusgroups.xml" (verified with diff); it is already in ruff extend-exclude.
- T1: Feed window is [now, now + days); read_feed/rank get start=now so only events with start > now (or == now) come back; no extra SOONEST 30-min cutoff.
- T1: The passed-in `now` is the clock for everything: memory-cache age, fetched_at written to the file, and the 48 h file-cache check.
- T1: Memory cache is a module dict `_memory` keyed by (data_dir, events_url, campus, days), so tests using a tmp_path data_dir are isolated without resetting module state; served events are re-filtered to start > now.
- T1: A missing, corrupt or naive-timestamp cache file is treated as no cache and raises EventsUnavailable("Sun Devil Central isn't answering") chained from the fetch error.
- T1: Catches (Exception, SystemExit) around the threaded fetch, because the script calls sys.exit on feed errors.
- T1: Added one extra test beyond the plan: test_memory_cache_skips_second_fetch (second call within 6 h does not fetch again).
- T5: I checked the composio 0.30.0 API in the installed source (.venv/lib/python3.13/site-packages/composio). The calls are: connected_accounts.link(user_id, auth_config_id, *, callback_url=...) returns a ConnectionRequest with .redirect_url; connected_accounts.list(user_ids=, toolkit_slugs=, statuses=) returns an object with .items; connected_accounts.delete(nanoid); tools.execute(slug, arguments, *, user_id=, dangerously_skip_version_check=) returns a TypedDict {data, error, successful}. The 'already connected' exception is composio.exceptions.ComposioMultipleConnectedAccountsError.
- T5: busy_blocks first calls is_connected and returns None when the member has no ACTIVE account. The whole body, including that check and the parsing, sits inside one broad except (with noqa BLE001), so any failure returns None and a warning that logs only the exception type name, never secrets or event data.
- T5: busy_blocks reads every calendar under data.calendars, not only 'primary', and builds each BusyBlock from start/end only. Pydantic parses the ISO strings into datetimes that keep their timezone.
- T5: disconnect lists accounts filtered by user_ids only (all toolkits and statuses) and deletes each account.id, as in 'delete every connected account for that user id'.
- T5: Besides the 5 tests the plan lists, I added test_composio_user_id and test_is_connected_and_disconnect, which check the exact list() kwargs and the delete loop.
- T4: anthropic 2.3.0 AsyncAnthropic.messages.parse takes output_format (a type) and output_config and merges them into output_config.format, as I confirmed in the installed SDK source. The fallbacks beta (header anthropic-beta: server-side-fallback-2026-07-01 plus extra_body fallbacks=default) was accepted by the live API, so I kept it.
- T4: LLM.parse turns pydantic.ValidationError into LLMError as well as anthropic.APIError. The SDK's parse_response can raise ValidationError on bad JSON, and letting it through would bypass the planner's LLMError fallback (Review Focus 5).
- T4: The output models (RequestOut, StanceOut, StancesOut, DecisionOut, LearnedOut) are plain pydantic models in squad/agents.py with no Field constraints. All clamping, truncation and filtering happens in code, as the plan says.
- T4: Local time in agents.py comes from a module constant TZ = ZoneInfo('America/Phoenix'), the same value as settings.tz, so the pure functions don't need settings passed in.
- T4: parse_request also drops weekdays outside 0..6. It keeps only exclude_no_go keys that exist in NO_GO.
- T4: member_stances gives the member agent its private profile (interest labels, budget label, no-go labels, learned filters) and only that member's own violation detail_private strings. It keeps the first stance per event_id, returns stances in candidate order, and fills missing ones with the interest-score fallback.
- T4: The coordinator prompt lists per candidate: title, time, location, price, each member's name with score/10 and shared_reason, and 'Broken limits: <name>: <label_public>'. It never includes detail_private.
- T4: fallback_decision headline is f'{title}, {start:%a %-I:%M %p}' in Phoenix time. Tradeoffs are de-duplicated 'Someone has <label_public>', at most 3.
- T4: I appended '(false when nothing is broken)' to the flex_ok sentence in MEMBER_SYSTEM. In the live run the model set flex_ok=true even on events with no broken limit. The required wording is otherwise kept as given, plus short format hints (exact event_id, length limits, max one exclamation mark).
- T4: I added two tests beyond the listed ones: test_ok_returns_parsed_and_sends_effort (checks the model, output_format and effort, and that temperature/thinking are not sent) and test_none_output_raises in test_llm.py, plus test_learn_from_no_keep_true in test_agents.py.
- T6: confirm_view signature is confirm_view(plan_id: str, text: str) -> ui.LayoutView. The plan names a 'text: str' arg but its listed signature leaves it out. Yes button is success style, no is secondary.
- T6: who_line and results_card show 'a friend' for a voter id missing from names (Task 13 may count votes from non-members). Groups are joined with two spaces.
- T6: no_plan_card renders the near miss as 'Closest call: **{title}**\n🕖 <t:..:F> · <t:..:R>'.
- T6: results_card adds the '**Rides**' block only when there is at least one car or transit rider. The tz params on the cards are kept to match the interface but are unused, because Discord <t:> timestamps render in the viewer's local time.
- T6: CallsModal takes an optional 'existing: Member | None = None' to pre-fill phone, opt-in and quiet hours (default quiet hours '22-9'). JoinModal(existing=None) pre-fills the option defaults; budget is matched by budget_usd and seats by str(seats).
- T6: If a RadioGroup value comes back None on submit, JoinModal falls back to budget 'free' and seats '0', and CallsModal falls back to quiet '22-9'.
- T6: apply_calls: raw text must fully match [+digits spaces - ( )] with 10-15 digits, otherwise ValueError('phone'). A bare 10-digit number without '+' gets the '+1' prefix. Empty or blank input sets phone '' and call_opt_in False and still saves quiet_hours.
- T6: member_from_join on an existing member uses model_copy(update=...), which keeps phone, opt-in, quiet hours, learned filters, demo_busy and is_demo.
- T6: The Skip button in why_no_view is a plain non-persistent button (as the plan says). Its callback edits the message to a branded LayoutView with 'No worries 🙂'. It stops working after a bot restart.
- T6: preview_cards.py puts the repo root on sys.path so it can import squad and tests.fakes (the project is not installed as a package). It uses a full gateway login, looks for the thread in active threads, then archived ones, then creates it. The sample Plan is built inline because tests/fakes.py has no make_plan.
- T9: Checked the google-genai 2.33.0 API names in the installed source: client.aio.live.connect(model, config), session.send_realtime_input(audio=Blob), session.receive() (yields messages until one turn is complete, so the bridge calls it in a loop and stops when it yields nothing), LiveServerMessage.data and .tool_call.function_calls, session.send_tool_response(function_responses=FunctionResponse(id, name, response)). The config dict, including RECORD_ANSWER with a lowercase 'object' type, passes LiveConnectConfig validation.
- T9: Live check against the real API: connecting with gemini-3.8-live, response_modalities AUDIO and the RECORD_ANSWER tool works. A text 'hello' got 98,400 bytes of audio back.
- T9: Resampling: each group of 3 input samples gives out[2k]=in[3k] and out[2k+1]=(in[3k+1]+in[3k+2])//2. Leftover bytes that don't make a full 6-byte group are returned as carry. Byte order is swapped on big-endian hosts.
- T9: The 90 s limit and the 3 s goodbye wait are module constants CALL_LIMIT_S and GOODBYE_S, so tests can patch them. The 90 s timer starts after POST /call succeeds and covers the WebSocket, the Gemini connect and both audio pumps.
- T9: answered=True is set by the sidecar's {"event":"answered"} or by a valid record_answer call. The call hangs up GOODBYE_S seconds after the first turn_complete that arrives once an answer is recorded. seconds runs from Gemini setup to the end, rounded to 0.1.
- T9: nudge_call never raises. A non-200 from /call or any exception gives CallOutcome(answered=False), and only the exception type name is logged, so no secret can reach the log. If an audio pump fails, the answer already recorded is kept. {"cmd":"hangup"} is always sent in finally.
- T9: ws_connect is a callable(url) whose result is awaited to get the WebSocket. By default it is aiohttp ClientSession.ws_connect.
- T9: 'when' is formatted as plan.event.start in settings.tz with '%A %-I:%M %p'. 'going' is the names joined with ', ', or 'nobody yet' when the list is empty.
- T9: The catch-all except is marked noqa: BLE001 on purpose, because a failed nudge must not crash a flow (Review Focus 3).
- T9: Tests use a real aiohttp TestServer as the fake sidecar and a fake genai client built from real google.genai.types messages. The records-answer test also checks that 2,400 samples at 24 kHz reach the sidecar as 1,600 samples, the tool response is {"result":"ok"}, the model name, and the system prompt.
- T8: whatsapp-rust features copied from examples/voip-cli/Cargo.toml: sqlite-storage, tokio-transport, ureq-client, tokio-native, voip-relay-native, plus voip-mlow (the example's default codec). wacore uses features ["voip"], also as in the example. I left out the example's optional voip-opus (voip-encoded + voip-libopus) so the build doesn't need libopus.
- T8: Cargo.lock is committed so the build stays pinned to whatsapp-rust main at 9b9fdb7e (wa-voice is a binary crate). The task's file list didn't name Cargo.lock, but cargo creates it and the build needs it to be reproducible.
- T8: Calls use client.voip().call(&jid).audio(mic_rx, speaker_tx).start() with MLOW, the same as the example. The newest whatsapp-rust also has .audio_opus(..), and its docs say MLOW can drop the first ~1 s of what the callee says. If the live check loses short answers like 'yeah', switch that one call to audio_opus and add the voip-libopus feature.
- T8: The 'answered' event is sent when CallHandle::media_connected() turns true. This is checked every 200 ms. For an outgoing call it means the callee accepted and the media keys are installed.
- T8: 'ended' is sent when CallHandle::wait_ended() resolves. The reason is the first one recorded: 'hangup' (the client sent {"cmd":"hangup"}), 'bridge disconnected' (the WebSocket closed), 'max duration', or the Debug text of CallEvent::Closed (for example RelayDisconnected). If none was recorded it is 'ended'.
- T8: Audio from the client is cut into 960-sample frames (audio::bytes_to_frames) and goes into an unbounded queue. A pacer task sends one frame every 60 ms into a bounded(8) mic channel, and sends silence when the queue is empty, like the example's continuous microphone. This means bursty Gemini audio plays at real-time speed. The callee's audio goes into a bounded(64) speaker channel; frames are dropped when nobody reads it, which is the engine's loss-tolerant default.
- T8: POST /call checks in this order: 400 bad phone, 409 busy, 503 not connected (client.is_session_ready()). If start() fails it returns 502, which the contract doesn't cover; the Python side treats any non-200 as unanswered. A JSON body that doesn't parse gets axum's default 4xx.
- T8: Only one call at a time: a tokio Mutex is held across start(). GET /status uses try_lock, so busy is true while a call is being placed.
- T8: Safety nets: a call is terminated after 150 s even if nobody hangs up, and closing the WebSocket also terminates the call. Either way the sidecar can't stay stuck at busy/409.
- T8: 'paired' is an AtomicBool. It is set true on the Connected or PairSuccess events and false on LoggedOut, so after a restart it reads false for the few seconds before reconnecting. The QR string is logged and written to data/wa-qr.txt from on_qr_code, and the file is deleted on Connected or PairSuccess. The paths data/wa-voice.db and data/wa-qr.txt are relative to wa-voice/ and are already gitignored by the existing 'data/' pattern.
- T8: JID = <digits>@s.whatsapp.net, parsed as Jid. Resolving a LID (the plan's 'must be LID' fallback) is not implemented, because it can only be checked on a live call.
- T8: I added two small unit tests in main.rs (phone_validation and hangup_command) alongside the two required audio.rs tests (chunks_and_keeps_remainder and roundtrip_little_endian).
- T9: Goodbye fix: model_to_callee now ends only on a turn_complete after model audio has arrived following send_tool_response (flags `responded` and `goodbye`). The silent tool-call turn's turn_complete is skipped, and audio keeps going to the sidecar until the goodbye turn completes; then the bridge sleeps GOODBYE_S. I keyed on 'audio after the tool response' rather than 'the second turn_complete' because it holds whether the tool call comes with or without audio in its turn. If the model never speaks a goodbye, the call ends when the callee sends 'ended' or at the 90 s limit.
- T9: Hangup fix: I added a `_hangup(ws)` helper that does nothing if `ws.closed`. _bridge calls it in its finally, right after the pumps are cancelled and while still inside `async with live.connect(...)`, so the hangup no longer waits for the slow Live close (about 10 s). nudge_call's finally still calls `_hangup` as the 'always send hangup' fallback (connect errors, timeout before the session opens); it does nothing if the socket is already closed.
- T9: CallOutcome.seconds is now measured at hangup time (`ended`), not after the Live session close. If the timeout fires before the session opens, it is measured at return as before.
- T9: Test: test_nudge_call_records_answer now uses the real message order [[audio, tool_call, turn_complete], [goodbye audio, turn_complete]]. It asserts that both audio chunks (2*3200 bytes) reached the sidecar before it saw the hangup. FakeGenai takes an optional async on_close hook called from __aexit__. The test uses it to assert the sidecar got the hangup before the Live session close (the hook polls up to 1 s, because aiohttp ws.close() returns before the server reads the frame). The new test failed against the old bridge, and failed again with the in-session hangup line removed. It passes with the fix.
- T8: Fixed in code rather than in the docs: place_call now takes axum::body::Bytes and parses CallRequest with serde_json::from_slice. A parse error returns 400 {"error": "bad json: ..."}. A missing Content-Type header is accepted, so the plan's `curl -XPOST 127.0.0.1:8091/call -d '{"phone":...}'` works unchanged, and so does the aiohttp json= bridge call.
- T8: README and the plan's live-check command are unchanged because they are now correct as written.
